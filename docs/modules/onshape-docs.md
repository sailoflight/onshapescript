# `onshape_docs` module contract

Status: verified

## Owns

- Authored FeatureScript, REST API, MCP, browser experience, verification, and reference documentation under `onshape_docs/`.
- Vendored upstream reference material and its provenance.
- Offline quick/detail indexes and project-document index builders.
- Query APIs used by MCP tools for candidate search and exact detail retrieval.
- Documentation integrity, staleness, and local FeatureScript checks.

## Does not own

- MCP JSON-RPC registration and dispatch: `mcp_main`.
- REST credentials, live request transport, quota ledger, target state, and outputs: `onshape_rest_api_mode`.
- Persistent browser session, selectors, and UI actions: `onshape_browser_mode`.
- Repository-level role routing and module contracts: project `docs/`.

## Entrypoints

| Kind | Path or symbol | Purpose |
|---|---|---|
| Documentation map | `onshape_docs/README.md` | Domain lookup order and directory ownership |
| Project-doc query | `onshape_docs/query/project_docs.py` | `docs_list`, `docs_search`, and exact section retrieval |
| FeatureScript query | `onshape_docs/query/fs_reference.py` | Quick/detail FeatureScript lookup |
| REST reference query | `onshape_docs/query/onshape_api_reference.py` | Endpoint and schema lookup |
| Project index build | `onshape_docs/scripts/build_docs_index.py` | Authored project docs to `onshape_docs/index.json` |
| Reference builders | `onshape_docs/scripts/build_*_index.py` | Vendored raw inputs to quick/detail indexes |
| Local FeatureScript guard | `onshape_docs/scripts/fs_local_check.py` | Zero-call structural and symbol checks |
| Integrity verifier | `onshape_docs/verification/verify_docs.py` | Offline documentation/reference validation |
| Tests | `dev/tests/test_project_layout.py`, `dev/tests/test_mcp_server.py` | Ownership, query, and MCP tool behavior |

## Contracts and invariants

- Query order is candidate index, one exact entry, then a complete authored or raw source only when necessary.
- Generated JSON indexes are tool inputs, not normal reading material.
- Authored Markdown remains canonical for project guidance; generated indexes record source hashes and must be rebuilt after indexed changes.
- `reference/raw/` is provenance and build input, not the first lookup tier.
- Experience documents contain reusable verified conclusions; verification contains evidence; reference contains upstream material.
- Source conflicts must retain version/date scope and cannot be silently merged.
- Fetching a source and building its index are separate operations; tests and development verification remain offline.

## Dependencies

- Allowed: Python standard library, vendored authored/raw files, and module-owned query/index helpers.
- Forbidden: importing REST credentials or browser sessions into offline query paths; using a full generated index as a routine agent read; writing authored guidance from generated output without an explicit source process.

## Data, configuration, and generated files

| Item | Owner | Behavior | Source of truth |
|---|---|---|---|
| Authored guide/experience/verification Markdown | `onshape_docs/` | Human/agent maintained | Markdown files |
| Vendored raw reference | `onshape_docs/reference/raw/` | Fetch/build input | Upstream material plus provenance |
| Quick/detail reference indexes | `onshape_docs/reference/quick/`, `reference/index/` | Generated | Raw reference plus builders |
| Project-doc index | `onshape_docs/index.json` | Generated | Registered authored Markdown plus builder |
| Repository tool reference | `docs/generated/TOOL_REFERENCE.md` | Generated by a docs script | MCP registered schemas/handlers |

## Verification

| Change | Required verification |
|---|---|
| Indexed authored project docs | `python3 onshape_docs/scripts/build_docs_index.py` then `python3 onshape_docs/verification/verify_docs.py` |
| Project-doc query or ownership | `python3 -m unittest dev.tests.test_project_layout dev.tests.test_mcp_server -v` |
| FeatureScript checker/index code | Matching tests plus `python3 -m py_compile onshape_docs/query/*.py onshape_docs/scripts/*.py` |
| Generated tool reference | `python3 onshape_docs/scripts/build_tool_reference.py --check` |
| Raw/upstream reference refresh | Use the documented fetch/build workflow; do not enable live REST during regression testing |

## Documentation triggers

- Adding an indexed authored page updates the builder registry, documentation map, tests, and generated index.
- A reusable verified behavior change updates experience and links its evidence.
- A reference refresh rebuilds the matching indexes and verifies hashes/health.
- Repository-level role or module routing changes belong in project `docs/`, not domain experience.

## Unknowns

- Upstream material may be newer than the vendored snapshot; use the version tools and report scope instead of assuming freshness.
