# 三方建模合作：真正起作用的九条做法（2026-10-04，按证据复盘）

**这一页回答目标④"加强建模合作的具体做法"**。它不是愿望清单，而是**从已经做过的三次协商里反推**：
哪条做法真的改变了结论、避免了什么错。每条都给出可核对的证据（工具 / 文件 / 提交）。

## 1. 读对方的**产物**，不读对方的**信**

信里的数字是**声明**，产物里的数字才是**读数**。第三次协商（CadQ）就是这样做的：
本平面用自己的实现重算它交付里的 70 个 STL —— **坐实**了它的界（相对偏差 `2.414e-06` 只在离原点最远的
那件上成立，399.9 mm），同时**否掉了**它的解释（它说偏差来自"朴素 `+=` 求和"，实测求和顺序只值 `2.4e-13`）。

**证据**：`docs/roadmap/THREE_PLANE_CADQ_CROSS_READ.md`；`dev/tools/cadq_tessellation_cross_check.py`（9/9 规则，exit 0）；
提交 `23788a9`。**避免的错**：把一个错误的成因写进接口文档，让三家据此做优化。

## 2. 一条规则**只有在量它的那一方确认后**才绑定；确认之后**本平面还要自己复现**

协调方把 R13 的准入设成条件句（"够格绑定，但要**量出它的那一方本人确认**"）；MeshQ 一句话确认后，
本平面**没有只凭那句话就翻状态**，而是先读它的 2×2 真跑把数字与百分比对齐，再绑定。

**证据**：提交 `9d64403`；台账 3.11 / 4.21；接口 §4.1。
**避免的错**：把"某家说了算"当成"事实"——确认是**授权**，不是**证据**。

## 3. 未确认的规则要**机器可见且不伤人**

提议中的规则会被跑出来、进 `proposedRefusals`、说出"假如绑定会拒什么"，但**绝不进 `refusals`、绝不影响 `ok`**。
R13 曾经如此，现在 R14 如此（相对精度界必须说明适用范围）。

**证据**：`dev/verification_report/rules.py` 的 `status` + `AGREED_RULE_IDS`/`PROPOSED_RULE_IDS`；
`dev/tests/test_verification_report.py::RelativeBoundWithoutScope`（提议→只报告、绑定→拒、可满足→通过）；
提交 `13d9958`。**避免的错**：要么"一条没被确认的规则开始拒人"，要么"提案被静默丢掉"——两头都伤合作。

## 4. **会自己关掉的检查**：把缺陷写成规则，而不是写成抱怨

发现对方的缺口时，同时交出**一条现在 FAIL、对方补上字段后自动 PASS** 的命令。
本仓现有三条这类检查（`--check` 只报事实与缺口，FAIL 数就是缺口数）。

**证据**：`dev/tools/print_fit_cross_read.py`（3/5，E6/E7）、`dev/tools/per_piece_identity_cross_read.py`（3/5，名字与寻址声明）、
`dev/tools/cadq_tessellation_cross_check.py`（9/9）；提交 `abaa5d9` / `fd888d6`。
**避免的错**：把接口问题变成"你说我说"——判据落进代码后，双方看的是同一条输出。

## 5. **先修自己**再要求别人

R14 一落地，第一条被它点名的是**本平面自己发出的读数**（对端切片 `c_S`，非零相对界没写范围）。
本平面在**同一个提交**里补上 `scope`，并加一条测试**走查自己的夹具**。

**证据**：提交 `13d9958`；接口 §4.2；`test_this_planes_own_records_pass_the_rule_it_proposes`。
**避免的错**：只约束别人的规则会被读成"单方面要求"，还很容易被对方一句反例打回来。

## 6. **证据要分级，错了要公开更正**

上一轮把对端最小壁厚记为 `unknown`（**来信级**），本轮重读它的记录，实测是
`heuristic` + 方法 + `min_mm 4.0` + 已知失效场景 —— 文档更正、对端收到更正、台账记下这次更正。

**证据**：`THREE_PLANE_PRINT_FIT_BOUNDARY.md` §2；台账 4.24；提交 `fd888d6`。
**避免的错**：一条"待核"的转述变成别的平面会据此规划的"事实"。**分级是给未来的自己留的刹车。**

## 7. 一个运行器是**唯一权威**，适配器只许抽字段

报告的真消费者是**共享运行器**，不是逐平面的适配器。MeshQ 的 D1 选择了同一立场（"拒得明白"：
打印实际读到的 schema + 顶层键 + 一行退 2，并明确**不**把抽取器扩成第二个运行器）。

**证据**：`dev/verification_report/runner.py`；`CROSS_WALK.md` §8；提交 `20a7351` / `23788a9`。
**避免的错**：三家各写一份"什么算通过"，判决出现第四、第五份说法。

## 8. 对方做得好的地方，**点名引用**

MeshQ 的 `overhang` 带 `threshold_deg` / `axis` / `worst_tilt_deg`（判据与判定一起走），
被本平面引为**正例**去对 CadQ 的悬垂表（同一输入两个答案、判据没跟出来）；
MeshQ 的"**一个导出物一个摘要 + `objects[]` 声明覆盖面**"被写进逐件身份文档当正面例子。

**证据**：`THREE_PLANE_PER_PIECE_IDENTITY.md` §1；给 CadQ 的 310 号信；给 MeshQ 的 317 号信。
**避免的错**：只会挑错的三方协作很快会退化成互相防守——引用是**低成本高回报**的动作。

## 9. 结论**落仓**、台账逐行、送达**用收据工具**

每个结论都落成仓内文件（不是聊天记录），台账逐行可追（现 39 行），送达判据用
`mail-delivery-receipt.sh` 的 `found/不是影子`，**不用** send 的返回值。

**证据**：`docs/roadmap/THREE_PLANE_*.md` 七个文件；`THREE_PLANE_NEGOTIATION_LEDGER.md`；
本会话所有出站信的收据核查（如 307/310/311/315/316/317）。

## 附：第四个平面要接进来，最少要做什么

1. 声明你的 **schema id** 与产方身份；2. 每个零件给**内容摘要** + `sha256_stable` 与依据 + `label`（可为 null，
   但要显式）+ 一句**"地址就是这个摘要"**；3. 判据（阈值、轴向、采样）**跟判定一起走**；
4. **不要**给机器状态（包络/行程/摆放）或"可打印/可接受"这类**结论**盖章——那是消费方的状态；
5. 相对界要说**在什么范围内成立**（R14）；6. 读数缺席、判据缺席、检查器没跑，**三层各有责任方**。

做到以上，本仓的 `runner.py` 就能读你（`--ingest`），三家也能用同一条 `--check` 与你对话。
