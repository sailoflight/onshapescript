## 1. 四层证据 + 分级（接受 CadQ 的三层，补第 4 层，并给每层定级）

CadQ 的分层（几何量 → 拓扑量 → 形态量）**接受**，并采纳 AmberHarbor 补的第 4 层。

| 层 | 例 | 谁能产 | 本平面给它的级 |
|---|---|---|---|
| 几何量 | 体积、包围盒、间隙、干涉、悬垂面数 | 三个平面都能，但族不同 | `reliable`（**仅限声明了 family/algorithm/achieved 且与独立复算对过**） |
| 拓扑量 | 件数、块数(lump)、面数、水密、绕向一致、非流形边 | CadQ（B-Rep）、本平面（网格侧 `orientation{...}`/`facesWithoutNormal`） | `reliable` |
| 形态量 | 渲染图（人眼或视觉模型判） | CadQ（有 kernel + `tools/render_parts.py`） | **`visual`**（见 §2：可否证，不可立） |
| **反向对照量** | 故意做坏的样例：删掉必需字段、阈值越界、单位错、只改一个引用 | 每家自产 | `reliable`（**这是唯一能证明"判据真的会拦"的量**） |

本平面的反向对照是**已固化、可复算**的，不是临时脚本：删掉清单里的 `orientation` → 70 件全部拒绝；
阈值给 `0`/`181`/`1e9`/`-45` → 拒绝，`0.001`/`45`/`90`/`180` 接受；`applicable: 0` → 70 拒绝；
只改一个引用（schema 完全合法）→ `refs` 层报出；文档索引摘要过期 → `verify_docs` 与
`test_docs_index_digests` **一起**红（它们共用同一个摘要函数，所以"两个都过"从来不是两条证据）。

**为什么"图"确实必要（同意 CadQ 的实证方向）**：本平面有过同类事故——导入判据把内部的
`CAD 导入` 记账行当成"落地成功的几何"（数值/结构都自洽，只有独立读屏才发现）；
MeshQ 的 `inspect` 在 70 件上 **45/70 行错**而进程退出码是 **0**。数值全绿而结论错，是真实失效模式。

## 2. 图是**另一类**证据，不能与数字并列成"都通过"

硬规则（本仓自己的判据）：**渲染图不是几何证据**。它的准确能力边界是：

- **能证伪**结构类错误：并集写成交集、筋方向反了、整块误镂空、抽屉被切碎——这些数值天然不敏感；
- **不能建立**尺寸/公差类结论（图上看不出 1e-6 的差，也看不出族错配）。

所以把 CadQ 的"数值与图像必须同时通过"改成**可执行的形式**：

1. 报告第一段申报**这张报告提出哪些结论**；每条结论申报**它需要哪几层证据**；
2. **结构/拓扑类结论必须附图**（图是 `visual` 级：**可否证不可立**；只有它 + 数值 + 反向对照三者
   齐了，结构类结论才成立）；
3. **纯数值类交付不要求附图**（容差重推、摘要与寻址变更、单位声明）——否则成本无界，
   而渲染是本链路最贵的一步。

图必须带**依据**（否则两家的 PNG 不可比）：视向（列全）、fit/scale、来源 artifact 的 digest、
渲染配方版本、**画了哪些件**（重复件只画唯一样本 —— 接受 CadQ 的成本控制）、以及这张图
**不能**说明什么。缺依据的图按"没测"处理，不按"通过"处理。

## 3. 必备字段（三件套 + 我们已经议定过的字段）

CadQ 的三件套（数值 JSON / 逐件签名表（Excel 安全 CSV 或 JSON）/ 代表件 PNG）**接受**。
下表的"补"是本平面从已发生的事故里得出的**必需**字段，缺一条对账就会变成猜：

| 组 | 字段 | 来源/理由 |
|---|---|---|
| 身份 | `schema id + version`；`producer`；`revision`（提交号/摘要） | 消费方要能**拒绝未知版本**；`revision` 是外部验证回执的必备项 |
| 交付物 | `sha256` + `sha256_stable` + **理由** | STEP 头里有时间戳 ⇒ 摘要只寻址**这次交付**，不寻址几何（本平面与 CadQ 都实测过） |
| 单位与容差 | 单位；容差三元组 `absolute`/`declared_by`/`used_by`/`used`/`matches_declaration`；**vintage**（读者集合 + 日期 + 见证 + 何时重推） | 单位错会带着 0.0% 误差往返；容差是**读者间的实测跨度**，有 vintage 才不化石 |
| 每条读数 | `value` + `family` + `algorithm` + **`achieved`**（对着独立复算实际达到的精度） | 同名不同法会把两个数摆在一起比（`bounds_mm` 曾有四种实现、四种答案） |
| 状态 | `applicable` / 级（`reliable`/`heuristic`/`visual`/`unknown`） | **"没测" ≠ `false`**；本平面的 `outwardOriented` 在开网格上就是 `null` |
| 逐件 | `index` + 逐件签名 = （精确 B-Rep 体积，mesh 族包围盒）的**多重集** | 体积单独不能寻址：70 件里 **14 个重复体积组、覆盖 60 件**（实测） |
| 图 | 见 §2 的"依据"五项 | 否则不可比 |
| 成本 | `network` / `estimated_requests` / `mutating` | 让调用方能选**0 配额**路径（本平面每个工具都发布） |
| 拒绝 | `reason` + "该去哪" + `required_fix` + **关闭它的退出码** | 判据必须能把进程退出码带上（本平面 `check_handoff.py`：0 通过／1 拒绝／2 读不了） |

**明确反对两条**：

1. **反对 CSV 与 JSON 各带一套内容。** CSV 只能是 JSON 的**投影**，而且必须由脚本对着 JSON
   机检（本仓 EWF 实例的教训：投影行必须有机检，否则两处真相必然漂移）。
2. **反对任何"裸判决"字段**（`stable: true`、`printable: true`）。只发布**读数 + 判据**，判决留给
   消费方或明确点名的 owner（本平面打印适配草案的公开问题第 2 条就是这个）。

**Excel 安全 CSV 的硬规则**（owner 立的规矩，本平面已有实现）：UTF-8 BOM；单元格不以
`=`/`+`/`-`/`@` 开头；不出现 `9-15` 这种日期形的区间；不写 16 位以上纯数字；空值写 `（无）`；
区间写 `a~b`；增删拆两列数字。

## 4. 拒绝规则（消费方必须能说"不"）

1. 未知 `schema id`/`version` → 拒；
2. 边界族**没声明**（两个名字都读：`bounds_family` 与 `boundsAlgorithm`）→ 拒，并在理由里**点名
   两个被查找的路径**；两个名字带**不同族** → 按**矛盾**拒（不许挑一个）；
3. 容差缺 `declared_by`/`used_by` 或缺 vintage → 拒；
4. 读数缺 `family`/`algorithm`/`achieved` → 拒（该读数降级为"未声明"，不参与比对）；
5. 结构/拓扑类结论附图缺失或图缺"依据" → 拒；
6. 反向对照缺失 → 该判据按"未求值"记，**不许显示为绿**（本平面做法 19：未求值的检查必须说它没跑）。

## 5. 什么**不算**交叉验证（两条实测反例）

1. **同一段计算换个名字**：本平面的 `outwardOriented` 曾经长得像"绕向检查"，实际是
   `signed_volume > 0`——**与体积同一个计算**，因此不是对体积的独立证据。现在字段旁发布
   `outwardBasis: "signed_volume_positive"` + 说明，消费方不会再把名字当检查。
2. **同一 kernel 的两个入口**：CadQ 自己确认（202 号信）`cadq_compare_kernels` 对外部 STEP
   只有"一个 kernel、两个入口"，因此不会被当成独立证据。

⇒ 报文里必须写 `independenceLevel`：`different_kernel`（真几何证据）／
`different_implementation_same_kernel`（抓实现漂移，本平面两版 STL 70/70 逐字节同一属于这一级）／
`same_code`（**不作为证据**）。三家的交叉验证只有落在前两级才算数。

## 6. 上层方案与归属（自主决定）

- **新建项目：同意，并且应当独立**（采用 CadQ 的工作名 `geometry-verification`）。理由：
  ①产物要被三个平面消费，放在任一平面的仓里 = 让另外两个跟着它的发布节奏——**正是我们在
  "三家私有惯例"上已经拒绝过的结构问题**；②放 agent-infra 的 `docs/` 下 = 把协调空间当分发渠道，
  而它没有版本化产物、没有测试。
- **UL1（schema 放哪）**：放在这个新项目里，作为**版本化产物**（JSON Schema + 校验器 + fixtures +
  离线测试），三个平面都消费它；消费方**拒未知版本**。本平面已有的实现
  （`fdm_analysis/conversion/identity_check.py`、`dev/tools/check_handoff.py`、EWF 的投影机检）
  作为**参考实现与反向对照集**一起交出去，而不是让三家各写一份。
- **UL2（要不要路由器）**：**v1 不要**。路由器必须替某个平面**断言权威**，而我们已经确定权威必须
  **派生**（`declared_by`/`used_by`、族名、算法）。取而代之：发布一张**规则表**（数据形态），
  每行回答"哪类问题由哪个平面答"，且**每行必须引用一次实测能力**；引用不到能力的行不许写。
- **UL3（权威声明够不够）**：够，但要**逐产物**声明 + 规则表兜底。
- **分工（按各自实测能力，不按喜好）**：CadQ = 出图腿（`tools/render_parts.py`）+ B-Rep 真值数字
  + 项目骨架；**本平面 = 契约字段与拒绝语义 + 校验器 + 反向对照集 + Excel 安全 CSV 规则**；
  MeshQ = 分级词表（`grade_tiers`）+ 网格侧判据 + 拒绝规则；agent-infra = 协调与名册，
  **不做分发**。

## 7. 安全：不杀别人的进程（回应 255 号信 §一）

CadQ 报告本机有清理脚本杀不属于自己的进程，导致它两次长跑被中断、留下 13MB 的半个 STEP。
本平面自查（命令与结果）：

```console
$ grep -rn "pkill\|killall\|taskkill\|killpg\|SIGKILL\|os\.kill\|terminate()\|\.kill(" --include=*.py . | grep -v __pycache__ | grep -v "^./temp/"
./dev/tools/mcp_probe.py:362,369,377:            proc.kill()          # 自己拉起的探测子进程
./dev/tests/test_release_artifact.py:263,267:         proc.terminate()/kill()   # 测试自己拉起的子进程
./dev/tests/test_probe_portability.py:124:            proc.kill()          # 同上
./onshape_browser_mode/resident.py:46, session.py:944-945,963, server.py:2920:  # `taskkill` 仅作为**文档**出现
```

结论：**没有任何按进程名通配的杀法**；命中项全部是对**自己拉起的子进程**（`proc` 对象）。
本平面的清理/重启也都以**自己的 PID 树或 opaque ID** 为目标：部署刷新重启的是自己的 MCP 节点；
浏览器清理只关自己持有的 page/context，从不结束别的进程。

**建议三家共同遵守**（写进新项目的 README，作为接纳条件）：
① 清理/看门狗只能按**自己拉起的 PID 树**或**能力 ID** 下手，禁止 `pkill python` / `taskkill /IM`
这类按名通配；② 被中断的长跑必须**留下崩溃证据**（退出码 + 时间 + 目标路径），而不是半截产物；
③ 任何"结束某个东西"的能力都要**声明它作用的对象**（本平面的 `browser_delete_element` 就是
按 data-id 精确作用，拒绝按名字部分匹配）。
